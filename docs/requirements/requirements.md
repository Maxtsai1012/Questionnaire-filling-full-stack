# 動態問卷系統修改需求

本文件整理本次附件需求與既有 PDF 規格。實作必須沿用現有專案，不升級框架、不清除既有 MySQL 資料，資料表變更一律以向下相容 migration 提供。

## 使用者與權限

- 訪客可瀏覽、填寫公開且進行中的問卷；點「新增問卷」時提示「請登入建立表單!!」後導向登入。
- 會員可新增問卷並填答；會員資料由登入身分自動帶入，不信任前端傳入的身分欄位。
- 管理員登入後導向管理頁，且只有管理員可呼叫 `/api/admin/**`。
- 登入與註冊共用既有 UI 風格，登入後依角色導向。

## 驗證與填答

- 搜尋、新增、修改問卷時，結束日期不得早於開始日期；相同日期允許。
- 訪客姓名只允許中英文與合理空白；手機正規化後須為台灣 10 碼 `09XX-XXX-XXX`；Email 前後端皆驗證。
- 多欄位錯誤必須同時顯示，欄位修正後只清除該欄位錯誤；invalid 時不得呼叫 API。
- 後端重新驗證必填、問卷狀態、動態題目、選項與重複填答，主回覆與回答明細同一 Transaction。
- 重複規則依 2026-08-03 最新確認改回 `questionnaireId + normalizedEmail`；同一 Email 不得重複填寫同一份問卷，但可填寫不同問卷。
- 已登入會員可從導覽列進入修改會員資料頁；姓名、手機與密碼可修改，登入 Email 唯讀。
- 後台問卷列表預設查詢並顯示全部狀態，不以發布狀態過濾。

## 統計圖

- 沿用 Chart.js，依 `docs/ui-reference/Chart.png` 調整為有間隔、圓角、上方圖例的甜甜圈圖。
- 無資料時顯示明確空狀態，不建立空 Chart。

## 資料保存

- 正式送出須寫入 MySQL 的 `quiz_response` 與 `response_answer`。
- 不修改 `init.sql` 來破壞既有環境；新增獨立 migration SQL。
- GitHub 只保存 schema/migration，MySQL Server 內實際資料須另行匯出才可跨電腦同步。
